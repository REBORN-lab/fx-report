# 外汇周报生成

设 TODAY = 今天(UTC),WEEK = TODAY 的 ISO 周号(格式 YYYY-Www,如 2026-W33,
用 `date -u +%G-W%V` 取得)。输出 `reports/weekly/WEEK.md`。

## 第 1 步:收集素材(脚本辅助,数字禁止心算)

1. 列出最近 7 个自然日(TODAY-6 … TODAY)中存在的日报:
   `ls reports/daily/ | sort`(对照日期清点)
   记录:覆盖日报 N 份、日期列表、缺失日期列表。
2. (复盘计数已由下面第 3 项的 digest 提供,不再单独跑 stats —— 两处窗口定义
   不同,并存会让同一份周报有两个都"合法"的计数。)
3. 跑周度聚合器,输出原样照抄:
   `python3 scripts/weekly_digest.py --week WEEK`
   它写出 `state/weekly-digest-WEEK.json`,内含各币种周涨跌/周区间/定盘次数、
   事件计数、缺漏按源统计、verdict 计数。**周报里的跨日数字一律逐字引用它**,
   不得自己从日报里心算(与日报引用快照 derived 同一模式);某项为 null 时
   写"不可得",禁止补算。
4. **阅读顺序:先聚合文件,再各日报的「## 速览」表,最后才回原文取细节。**
   主线聚类的输入是**各日的判断**,不是各日的全文:
   1. 读 digest,拿到各币种周涨跌、周区间、缺漏按源统计、verdict 计数;
   2. 逐份读 N 份日报的 `## 速览` 表(每份五行:币种 / 条件方向与时限 /
      核心依据 / 失效条件),把这 5N 行按**驱动变量**归拢成 3–5 组 ——
      这一步就是本周主线的雏形,同一驱动变量下跨币种的行必须归进同一组;
   3. 只在写某条主线的"标的影响"与"证伪条件"缺具体依据时,才回去读那几份
      日报的对应币种节与"## 昨日观点复盘"节取原文;
   4. 各日报的"## 附录 C:数据缺漏与影响"逐份看过,供缺漏汇总用。
   逐份通读全文只会让主线退化成"按天复述",本仓库实测的周报正是这个形态。
5. 读 `state/calendar-*.json`(多个文件时取文件名字典序最大者,与采集层一致),
   摘出未来 2-3 周内(TODAY+1 … TODAY+21)的日程条目供"下周关注"引用——只准
   摘文件里实际存在的条目,文件没有的类别不得凭记忆补;年历过期或缺失时记入
   缺漏汇总。
6. 跑周报附录 A 生成器:
   `python3 scripts/appendix.py --mode weekly --input state/weekly-digest-WEEK.json`
   它把附录 A 整块打到 stdout,**第一行就是该块自己的标题行**。第 2 步把这一块
   **原样贴进周报**:一个字符都不改、不补、不删行、不改行序。三类结论句
   (事件 / 公告 / 定盘与区间)与口径差异说明全部由这一块承担,你不转抄。

**N 为 0 时终止并报错(无素材不生成周报)。N < 3 时照常生成,但覆盖声明
必须写明缺失日期(spec"日报不足"场景)。**

## 第 2 步:生成周报(LLM)

只依据第 1 步素材写 `reports/weekly/WEEK.md`,模板:

    # 外汇周报 WEEK

    > 覆盖日报:N 份(<日期列表>);覆盖区间 <window_from> 至 <window_to>;
    > 缺失日期:<列表,无则写"无">;<digest 的 `skipped` 非 0 时追加
    > "另有 <skipped> 份快照因损坏被跳过">
    > (`days` 分母以覆盖区间为准。陈述数量时一律说「覆盖区间内」,**不要说
    >  「本周」**——区间是否恰好等于整周需要日历算术,而你禁止做算术;
    >  `skipped` 不说明会让读者把削过的分母当全周)
    > 复盘图例:命中/未命中=触发发生且方向核对有果;无法判定=已复盘但触发
    > 条件未发生或证据不足;未判定=尚未复盘。本行不含数字。
    > 全部观测口径、结论句逐字引用,以及它们对本周判断的影响,见附录 A、附录 B。
    > (这一行是正文里唯一允许指向附录的话;**不要在这里写附录里那些词**,
    >  见下方禁令 5)

    ## 本周主线

    ### 主线一:<一句话标题>(影响 <币种列表>)
    **宏观背景**:<这条线的驱动变量是什么、区间内它发生了什么变化>
    **传导机制**:<A → B → 汇率;B 只能取 利差 / 风险溢价 / 资金流 / 政策空间 之一>
    **标的影响**:<落到哪几个币种的什么价格事实上,数字逐字引 digest>
    **证据强度**:<这条线站在哪几个日期的哪条依据上(日期写全 YYYY-MM-DD);
      有无方向相反的证据,有就点出来。**不写条数、不写等级**>
    **证伪条件(T+N)**:<什么可观测事实发生,这条主线就不成立>

    (### 主线二 … 至多到主线五)

    ## 各币种一周落点

    | 币种 | 主线归属 | 周内价格落点 | 下周判断(时限) | 失效条件 |
    | --- | --- | --- | --- | --- |
    | USD | <主线N> | 基准货币,聚合文件无自身汇率读数 | <可观测触发> → 关注<方向>(T+N) | <可观测量> |
    (EUR / PHP / THB / BRL 各一行,五币种五行;
     「周内价格落点」逐字引 digest:周涨跌 <chg_pct_week>%、
     周区间 <range_low>–<range_high>;某项为 null 时写"不可得")

    ## 复盘汇总

    - <digest verdicts 的四项计数,原样照抄>(统计窗口同为覆盖区间
      <window_from> 至 <window_to>;区间外的观点不计入,不得说成「本周无观点」)
    - 明细(按 `verdict_details` 的 (verdict, 日期) 归并):
      「<日期>:<该组的币种列表> — <verdict>」。**归并行里不写条数**——
      条数要靠你数,而你禁止做任何计数;把币种名列出来,读者自己看得见。
      该字段为 null 时写「决策日志不可用,覆盖区间内复盘无法统计」,
      不得写成全 0
    - 结构性读法(一句):这个分布为什么是这样、下周用什么手段让它收敛。
      **不得据此改写任何 verdict**

    ## 下周关注
    -(≤5 条,每条 = 日期 + 事件 + 挂靠哪条主线 + 检验该主线的哪一段;
      只准摘年历文件里实际存在的条目,凭记忆补条目即违规)

    ## 附录 A:……
    (第 1 步 `appendix.py --mode weekly` 的 stdout **整块原样贴**,
     含它自己的标题行;这一块你一个字符都不写)

    ## 附录 B:缺漏汇总
    - [<source>] <缺失内容简述> 波及 <日期列表>/<币种范围> — 影响:<一句话>
    (按源聚类各日报缺漏节条目,同源多日合并一行,日期列表不得省略;
     第 1 步发现的年历过期/缺失单列一行 [calendar],日期填 valid_until 或
     TODAY;本节无任何条目时才写"无")

**节序固定,不得换序、不得增删节。**`## 附录 A:…` 那一行起是附录区;
主线、落点表、复盘汇总、下周关注全部在它之前,而观测口径类的话
(区间内至少几条、顶没顶到上限、哪几天没采到、口径可不可比)一律只在附录区。

**本周主线的硬形态:**
- `### 主线N` **3–5 条**,少于 3 条说明没聚类、多于 5 条说明没取舍;
- 每条五段齐全、顺序固定,一段一行,粗体行首一字不改;
- **本节不得出现任何列表行**(`-`/`*`/`1.` 开头的行)——列表一出现,
  主线就退化成要点罗列,而五段式正是用来强制"背景→机制→标的→证据→证伪"
  这条链的;
- **至少一条必须是跨币种相关性主线**:讲清若干币种的同向变动是同一个分母
  还是各自独立的事。没有这一条,周报就只是五份日报的拼接。

## 计数与结论纪律(独立成节,因为这里连续栽过十一次)

前十一次事故全部卡在同一步:报告拿着一堆计数,自己推「有没有、有几次」。
每加一条禁令,下一次就找到一条绕过去的路径——undated 堵上了采集覆盖没堵,
覆盖堵上了截断没堵,事件通道堵上了汇率通道没堵。所以现在**结论由脚本给出,
你只负责逐字引用**。

1. **三条结论句只准照抄,不准改写,而且不经你的手**:`fixings_verdict`
   (定盘与区间)、`articles_verdict`(事件)、`official_verdict`(公告)。
   它们已经把观测缺口(未采到的日历天数、损坏被跳过的快照、每日上限截断、
   无法解析的时间戳、未记录的定盘日)折算进结论。这三类句子由
   `scripts/appendix.py` 写进**附录 A 整块**,你按第 1 步第 6 项原样贴进周报:
   **不转抄、不改写、不摘出其中的数字另行造句,正文禁止出现该句**。
   **整句逐字**是唯一形态——校验器对周报做**精确子串包含**检查:改动一个字符
   (含数字、标点、全角半角)或整句缺失即判违规,所以那一块只能来自脚本
   stdout,不能手打。整块已经覆盖 14 个槽位(五币种 × 三类,其中 `rates`
   容器里没有 USD 是正常的,基准货币无定盘价,脚本会在那一槽写明理由),
   整块的完整性由脚本保证,不需要你逐句核对。
2. **禁止引用下列字段作为计数**:`fixings`、`*_sampled`、`*_distinct`、
   `*_in_window`、`by_date` 里的任何逐日值。它们都是**下界或原始样本**,
   不是"发生了几件事"。`fixings` 尤其不是定盘次数——定盘日未记录时脚本按同值
   合并,只会低估。**这类展开一律不进正文**——观测口径怎么算的,附录 A 已经
   逐字说过一遍,正文再说一遍就是把管道读数当成市场事实。
3. **禁止自行推出"确实没有""仅""全周只有"。** 正文里根本不谈"有没有、
   有几件":「没发公告」「无事件」「未发生」「仅 N 次」一类断言在正文一律禁止,
   它们对应的口径话(「至少」「只多不少」)只以脚本原句的形态待在附录 A。
   (**唯一例外**:复盘汇总那一行的四项计数是 digest 的原值逐字照抄,
   「无法判定」在那里是计数桶的名字,不是你推出来的断言,照写。)
4. **周区间不是区间内的真实高低点**,只是被观测到的那些价位的极值;
   附录 A 的 `fixings_verdict` 说了这一点,正文就不得把周区间写成"全周高低"。
5. **兜底是管道属性,只看 `fallback_days`。** 它统计"当日 GDELT 没采到、
   而官方通道当日采到了东西"的天数。为 0 就是本区间没有发生过兜底,
   不得因为「某天 GDELT 失败」加上「某条公告发布于那天」就说成兜底——
   那条公告可能几天后才被采到,当天并没有任何兜底。
6. **禁止任何减法与日历算术。** 需要"去重掉了几条"直接引 `*_dup_dropped`;
   digest 里没有的差值就不要写。
7. `*_cap_assumed_days` 非零表示那几天的快照没记录采集上限、是按当前代码
   推定的,引用截断结论时须注明"上限为推定"。
8. 两个通道口径不同,禁止相加。

**禁令:**
1. 一级/二级结构禁止按日期组织(不得出现 `## 2026-08-05` 式标题)。
   正文里提日期一律写完整形式 `YYYY-MM-DD`:写成 `08-07` 会被数字溯源当成
   两个裸数字拦下(校验器只识别完整日期形态)。
2. 数字只准逐字来自周度聚合文件(digest)、日报原文与年历文件原文;
   禁止自行计算或汇总数字。
3. 复盘汇总的计数行必须与 digest 的 verdicts 逐字一致。
4. 不得引用缺失日期的任何"数据"。
5. **正文零管道语汇。**附录 A 的标题行之前,禁止出现下列词:
   无明确驱动、采集失败、快照、无公告、官方公告条目、采集上限、原始样本、
   通道、条目、不可得(表格里某个 digest 项为 null 时的那一处除外)、缺漏、
   口径不可比、下界、seendate、URL。**也不许换个说法把同样的意思写进正文**
   ——"区间内未取得可署名的新增表述"与"采集失败"是同一句话的两种写法。
   缺漏本身是有价值的信息,但它的位置是附录 B,而且要写成"哪条主线因此降档",
   不是"哪一天没采到"。
6. **不写空转句。**一句话删掉之后周报信息量不变,就删掉它;
   尤其禁止把五份日报的同一段静态描述在主线里再复述一遍。

## 第 3 步:校验(脚本,不可跳过)

运行(**必须带 --digest 与全部当周日报**,否则数字溯源不生效):

    python3 scripts/check_report.py reports/weekly/WEEK.md --mode weekly \
      --digest state/weekly-digest-WEEK.json \
      --daily reports/daily/<日期1>.md --daily reports/daily/<日期2>.md ...

- 退出码 0:完成。
- 非 0:按违规项修改一次,重跑。
- 二次仍非 0:报告首行前插入 `> ⚠ 本报告未通过自动自检:<违规摘要>`,
  保留落盘,如实结束。

**结论句相关的违规码(退出码非 0):** `VERDICT_NOT_QUOTED` / `VERDICT_ABSENT` /
`VERDICT_EMPTY` / `VERDICT_MALFORMED` / `VERDICT_CONTAINER_MALFORMED`。
**处置以校验器打印的那一行为准** —— 每条违规行末尾都带「处置:…」,照它执行。
本文件**不复述处置内容**(理由同 fx-daily-report 第 5 步:散文里的第二份可被
整体反转,而脚本输出可以被精确断言)。唯一事实源是 `scripts/check_report.py`
里的 `DISPOSITION_QUOTE` / `DISPOSITION_SCRIPT_BUG`。

(周报侧结论句字段恒为必需,不会出现日报那两个降级码;
`VERDICT_SKIPPED_NO_DERIVED` / `VERDICT_SKIPPED_LEGACY` / `VERDICT_ENTRY_MISSING`
的处置见 fx-daily-report 的第 5 步。)
