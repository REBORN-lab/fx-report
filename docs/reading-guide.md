# 如何阅读日报与周报

给读报告的人看,不是给写代码的人看。读完你应该知道三件事:**哪几行值得花时间**、**每个判断怎么被检验**、**什么时候不该信它**。

---

## 一、这份报告是什么,不是什么

**是**:五个币种(美元 USD / 欧元 EUR / 菲律宾比索 PHP / 泰铢 THB / 巴西雷亚尔 BRL)每天一份的归因与情景推演,外加每周一份的主线聚合。它把当天采到的公开报道、央行公告、宏观读数和参考价拼成若干条**可以被下一次定盘证伪的判断**。

**不是**:行情预测、投资建议、实时盯盘工具。它没有仓位、没有目标价、没有胜率。

**一条硬规矩,值得你知道**:报告里的**每一个数字都必须能逐字回抄到当天的数据快照**,写报告的模型被禁止做任何计算——涨跌幅、区间、差值、实际利率全部由脚本算好,报告只准引用。校验脚本每次出稿都会跑一遍,数字对不上就不许发。所以你看到的数字可以直接用,但**推论要自己判断**。

---

## 二、三分钟怎么读

按这个顺序,读完就可以停:

1. **执行摘要第一条** — 模板要求它必须是当天最强的那条链,不是最新的那条新闻。
2. **速览表** — 五行,一眼看完当天全部判断。
3. 只对你关心的那一两个币种,往下翻它的**分歧与判断**那一环。

其余部分(驱动/传导/是否已反映的细节、复盘、附录)是给需要追溯的人准备的。

---

## 三、日报逐节

日报固定 11 节,顺序不变:

```
执行摘要 → 速览 → 美元 → 欧元 → 比索 → 泰铢 → 雷亚尔
        → 昨日观点复盘 → 附录 A → 附录 B → 附录 C
```

### 速览表:一天的全部判断压成五行

| 列 | 怎么读 |
|---|---|
| **条件方向(时限)** | 完整形态是「**可观测触发** → 关注**方向**(**T+N**)」。`T+N` 里的 N 指**定盘次数**,不是自然日——周末与休市日不计。 |
| **核心依据** | ≤2 项,带 `[@键]`,键对应附录 B 的完整出处。 |
| **失效条件** | 什么发生了就说明这条判断错了。**没有失效条件的判断不算判断。** |

**读表的两个要点**:

- **触发和失效必须是两件不同的事**。如果「触发位」就是当前价格、「失效位」在区间另一端,那么触发天然比失效容易发生——这类判断的信息量很低。好的报告会自己点破这一点(2026-08-14 那份就在表下写了一句「后三行不是三条独立判断……三条合起来是同一个方向的敞口」)。看到这种自我提示,说明当天确实没什么可说的。
- **同一个触发条件,后件不该天天变**。如果「比索升破上沿」今天证明 A、明天证明非 A,那说明后件是从当天新闻倒推的,条件句只是包装。

### 币种节:四环链条

正常情况下每个币种节是四行,**必须一环推一环**:

| 环 | 它回答什么 | 你该盯什么 |
|---|---|---|
| **驱动** | 昨天到底发生了什么 | 有没有**反向的一条**。模板要求只要快照里有反向标题就必须保留,单边叙事是可疑信号。 |
| **传导** | 它通过什么机制影响汇率 | 机制只有四类:**利差 / 风险溢价 / 资金流 / 政策空间**。看它是不是真的用上了「驱动」那一环,而不是另起炉灶。 |
| **是否已反映** | 这层在价里有没有 | 这是最容易被跳过的一环,也是最值钱的一环。「没有」比「有」更有交易含义。 |
| **分歧与判断** | 市场可能在哪一点上错、怎么检验 | 分歧点应当是前三环推出来的。**如果这一环可以直接删掉而不影响前三环,那这条链是断的。** |

**minimal 体裁**:某个币种当天既没有可用事件、也没有新数据、也没有新定盘时,它只会有一行,例如

> 本日可引的仍是 2026-08-13 那一条报道,无新增量;判断沿用那一版,条件方向与失效条件见速览。

**这是设计好的行为,不是偷懒。** 以前遇到这种日子,报告会用三段话讲「我们没采到」——三个小节标题分别承诺「昨日发生」「定价含义」「情景与触发条件」,三段交付的都是同一件事。现在由脚本判定该币种当天有没有增量,没有就只准写一行。

### 昨日观点复盘

对照前一个运行日发布的判断,逐条给结论。四个词的确切含义:

| 判定 | 含义 |
|---|---|
| **命中** | 触发条件发生了,且价格方向与判断一致 |
| **未命中** | 触发条件发生了,但价格方向相反 |
| **无法判定** | 触发条件**没有发生**,或该币种当天没有新定盘 |
| **未判定** | 当天新写下的观点,还没到复盘的时候 |

**为什么现在「无法判定」特别多?** 这是当前最大的短板,如实说明:

- 早期的触发条件大量绑在「事件源恢复」「数据补齐」这类**系统自身状态**上,次日无论涨跌都判不出对错——40 条里有 19 条是这个形态。
- 另有 10 条只是把 5 运行日区间边界复述一遍(「若升破上沿则关注区间上移」),后件是前件的同义反复。
- 还有 2 条**方向写反了**(2026-08-12 的欧元与泰铢):押走弱,条件却写成「跌破」。

模板已经改掉了产生这类条件的规则,新写下的判断必须绑每次定盘都会更新的可观测量。但**存量的判定不会回填改写**——它们是当时真实做出的判断,留着才看得见问题。所以你会在复盘节里看到报告自己点破「这条写坏在哪」,那是有意为之。

判定结论由脚本按价格机械算出,报告只准逐字引用,不许自己改判。

### 附录 A / B / C:什么时候需要翻

正文里看不到任何采集口径的话——「采到几条」「哪个源超时」「哪个指标换源了」全部在附录。这是刻意的分层:**正文是分析,附录是账本**。

| 附录 | 内容 | 什么时候翻 |
|---|---|---|
| **A:采集口径与结论句** | 脚本整块生成,一个字符不经人手。事件条数、采样上限、通道口径、公告存量背景、双源偏差 | 当你想知道「今天的证据到底有多厚」 |
| **B:出处** | `[@键]` 对应的标题、来源域名、发布时间 | 当你想核某条报道 |
| **C:数据缺漏与影响** | 每条缺漏 + 它让哪条判断打了折扣 | **每次都值得扫一眼**——它直接告诉你哪条结论证据不足 |

## 四、周报逐节

```
本周主线(3–5 条) → 各币种一周落点 → 复盘汇总 → 下周关注 → 附录 A / B
```

### 本周主线:周报的价值在这里

周报**不是**五份日报的摘要拼接,而是按**驱动变量**重新聚类。每条主线固定五段:

**宏观背景 → 传导机制 → 标的影响 → 证据强度 → 证伪条件(T+N)**

至少有一条必须是**跨币种相关性主线**——回答「这几个币种同向,是一个共同因子还是几件互不相干的事」。这类主线通常是周报里最有用的一条。

标题会写明它影响哪几个币种,例如:

> 主线一:方向由美元一端给,幅度由各自的实际利率给(影响 USD、EUR、PHP、THB、BRL)
>
> 主线二:雷亚尔是唯一对不上的一条,降息落地那天缺口还被拉开(影响 BRL)

**读法**:先看有没有一条主线明确说了「哪个币种对不上」。异常项通常比同向项信息量大。

### 各币种一周落点

一张表:币种 / 主线归属 / 周内价格落点 / 下周判断(时限)/ 失效条件。美元那一行会写明它是基准货币、没有自身汇率读数。

### 复盘汇总

三行:

1. **计数行** — 逐字引用聚合文件算出的数,报告不许自己数。
2. **明细** — 按判定与日期归并。
3. **结构性读法** — 这周为什么是这个分布、下周用什么手段收敛。

**第三行才是重点。** 计数本身容易误读:比如「命中 1 / 未命中 1」看着像五五开,而结构性读法会告诉你那两条决定性判定绑的是滞后两个月、写下当天条件就已成立的通胀读数,所以「真正被市场检验的是 0 条」。**只看计数行会得出相反的印象。**

## 五、读的时候要自己警惕的六件事

这些是报告结构本身带来的陷阱,即使每个数字都对也依然存在:

1. **「参考价停在 5 运行日区间上沿」多半是算术恒真。** 如果这周价格逐日单调走高,那么最后一天必然等于区间上沿——这是恒等式,不是市场证据。看到这句话被当成强信号引用时要打折。

2. **事件条数几乎总是下界。** 采集有上限、有过滤,附录 A 会写明「源返回的原始样本顶到其上限,滤后条数是下界」。**条数变化不等于事件面变化。**

3. **换源的数字与前值不可比。** 某个指标当天换了数据源时,期号会跳变、口径会变,报告只准陈述当期值,不许写「升至/降至」。看到某个宏观数字突然大幅变化,先确认是不是换源。

4. **公告不等于昨日事件。** 央行 RSS 只给「最新 N 条」、不按日期过滤,常常抓到上个月的存量公告。报告会标「存量背景,非昨日发布」,这类内容只能当政策背景,不能当当日驱动。

5. **`gnews` 通道的链接是跳转链,不是原文直链。** 所以出处一律以域名标注。要读原文得自己搜标题。

6. **不同日期的日报,验证强度可能不一样。** 校验器会打印它跳过了什么,例如 `VERDICT_SKIPPED_LEGACY`(快照代际过旧,当天的结论句没有经过逐字校验)。周报的缺漏汇总里会说明这周哪几天属于这种情况。**「通过校验」和「通过了全部校验项」不是一回事**,报告会把区别打印出来,不会假装。

## 六、怎么判断这份报告可不可信

三条可以自己验:

1. **数字**:随便挑一个数,去当天的 `data/YYYY-MM-DD.json` 里搜,应当逐字命中。搜不到就是问题。
2. **缺漏**:附录 C 的条目应当与快照的 `gaps` 一一对应,不多不少。多写一条是编造,少写一条是隐瞒。
3. **判定**:复盘节的结论词应当逐字来自脚本给出的方向核对句,不该有报告自己新造的结论。

如果你想让机器替你验,在仓库里跑:

```bash
python3 scripts/check_report.py reports/daily/<日期>.md data/<日期>.json \
        --brief briefs/<日期>-brief.md --mode daily --strict-brief
```

退出码 0 才算通过。**注意周报必须用 `--digest` 传聚合文件、并用 `--daily` 逐个传当周日报**,写成位置参数会被直接拒收(那条命令曾经静默放行过,现在改成响亮失败)。

## 七、当前已知的不足

写在这里而不是藏起来:

- **复盘判定仍有一半的决定权在写报告的模型手里。** 脚本已经能机械算出方向核对结果,但把它变成唯一结论、让模型没有语法可以改判,是下一步的工作。
- **本周(2026-W33)的决策日志与重生成后的日报存在脱节**:日报速览表发布的是新格式触发条件,而日志里存的是旧版写下的那批。复盘节会写明它引的是存档记录。新写入的观点已是新格式,旧条目会随窗口滚出。
- **正文里的「不许写采集失败」是位置规则,不是语义规则。** 它拦得住把管道句复制进正文,拦不住换一种说法表达同样的意思。真正压住它的是「没有增量就走 minimal 体裁一行带过」这条结构规则。
