## 第 2 对 — 结构化模板对推理质量的作用(task-b vs task-adversarial)· 处置:**调和**

- **task-b**:ICD 203、IMF RAM、BoE 情景合成三套结构化框架,作为改善「深度和逻辑」的手段推荐
- **task-adversarial F1**:结构化格式**实测降低**推理质量 —— `claude-3-haiku` 在 GSM8K 上由自由文本 86.51 掉到 JSON schema 下 23.44;作者排除解析错误(`parsing error rate ... is only 0.148%, yet there exists a substantial 38.15% performance gap`)

表面上一个说「加结构」、一个说「结构有害」,是同一对象(结构化模板)的相反事实。

**处置(调和,两者各自成立且适用范围不重叠)**:

| | task-b 的结构 | task-adversarial 批评的结构 |
|---|---|---|
| 作用时点 | **产出之后**的评审 rubric | **产出之时**的生成格式约束 |
| 作用对象 | 人/脚本检查成品是否满足九条标准 | 模型在生成时被迫按字段顺序填空 |
| 实测损害机制 | 不适用(不参与生成) | `100% of GPT 3.5 Turbo JSON-mode responses placed the 'answer' key before the 'reason' key` → 先答后编理由 |

**两者可同时成立**:把 ICD 203 当**事后清单**用没有 F1 的问题;把四环当**生成时的填空模板**则正落在 F1 的射程内。

**由此得出的可执行结论(本对矛盾的实际产出)**:生成顺序必须与呈现顺序解耦 —— 先写证据环(驱动/传导/是否已反映),再写判断环,最后由这些导出速览表与执行摘要;读者看到的顺序不变。当前模板的呈现顺序(执行摘要 → 速览表 → 币种节)若被直接当作生成顺序,就是 F1 的失败形态。

## 第 3 对 — 自动审计器能否测出「深度」(task-a vs task-adversarial)· 处置:**标注未决**

- **task-a**:推荐抄 econstack 的 `/econ-audit`(124 项检查 / 17 类,RAG 评级 + A–F 字母分),作为补「校验器只查数字、不验论证质量」的手段
- **task-adversarial F3**(IMF WP/26/35):LLM 评分器按**关键词与章节是否存在**打分,`without fully evaluating the depth or quality of that discussion`

同一对象(用 LLM 做报告质量审计)被给出对不上的事实:一方当作可用手段,一方实测它测不出深度。

**处置(标注未决)**:两者都有证据,但不能调和成「各自适用」—— `/econ-audit` 的 124 项检查里有多少是**存在性检查**(某节是否出现)、多少是**质量检查**(该节的论证是否成立),本轮**未取到该清单原文**(task-a 的 Gaps 明确记录:需 clone 读 `econ-audit/` 目录才能拿到)。在拿到之前,无法判定它是否恰好落在 IMF 论文批评的那一类里。

**要判定还缺**:econstack `econ-audit/` 目录下 124 项检查的逐条原文,并按「存在性 / 质量」二分归类。这是下一步最直接的收获点。

**不得**在缺这份证据的情况下把 `/econ-audit` 写成「已解决论证质量校验」——那正是 IMF 论文指出的失败形态在我们自己身上的复现。
