## Context

两份 skill 是纯 prompt 文本(LLM 执行指引),无代码逻辑;质量约束由 `scripts/check_report.py` 在运行时兜底。五条改进全部是 prompt 措辞的局部增补/替换,实现方式为直接编辑 markdown。约束:不改采集层/校验器源码;报告语言中文。

## Goals / Non-Goals

- Goals:采集失败日报告仍有数值锚点;事件筛选防单边化;周报前瞻年历;复盘 verdict 可读;缺漏汇总紧凑
- Non-Goals:不改快照 schema、校验器规则、测试套件;不新增脚本或配置

## Decisions

1. **①放在要点表"数据发布"行而非新增行**:数据发布行已有"只列 is_new_release 为 true 或与年历命中相关"过滤,在其后追加回退分支(该币种"昨日事件 top"为空时,可列快照 `macro` 中该经济体政策利率/最新 CPI,并标"(存量背景,非昨日发布)")。数字仍逐字抄快照 → 落在日报白名单(快照∪要点表)内,`NUMBER_UNTRACEABLE` 不会触发;若该经济体 macro 采集也失败则无值可引,如实写"无"——不与禁令 3(缺漏数据禁止引用)冲突,因为引用的是采集成功的 macro 值,失联的是 events 源。币种节仍写"昨日无明确驱动",背景参照只服务"情景与触发条件"的数值锚点,不构成事件归因(main spec"无明确驱动"场景不变)。
2. **②写进"昨日事件 top"行内注**:top-3 筛选准则(FX/货币政策相关优先;主线反向标题至少保留一条,无反向标题时不强凑)。纯选取指引,不引入新数字。
3. **③素材清单加第 4 条 + 修订禁令 2**:第 1 步补"读 `state/calendar-*.json`,摘未来 2-3 周内五央行/主要数据日程";禁令 2 由"数字只准逐字来自日报原文与 stats 命令输出"扩为"……与年历文件原文"。周报校验无数字溯源,`DATE_HEADING_RE` 只查节标题,列表项含日期安全。
4. **④图例作为复盘汇总首行**:一行文字、零数字:"无法判定=触发条件未发生或证据不足;未判定=观点尚未到复盘窗口"。"命中/未命中/无法判定"三 token 仍在节内,`REVIEW_TOKEN_MISSING` 不会触发。
5. **⑤替换缺漏汇总模板行**:`- <日期>: [<source>/<scope>] <内容>` 改为按源聚类:`- [<source>] 波及 <日期列表>/<币种范围> — 影响:<一句话>`;全周无缺漏仍写"无"。main spec"列出对应日期与缺失内容"在聚类格式下仍满足。

## Risks / Trade-offs

- [①被 LLM 滥用为常态行] → 措辞限定"仅当该币种昨日事件 top 为空时",且标注"存量背景"字样
- [⑤聚类丢日期明细] → 模板强制"波及 <日期列表>",日期不可省
- [prompt 变更无自动化断言] → 轻量验证跑全量测试(校验器测试不受影响)+ 对照 5 条逐项人工核对 diff
